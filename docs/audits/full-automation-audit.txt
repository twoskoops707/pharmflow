================================================================================
ROOT CAUSE: single-sequence-only bug
================================================================================

PRIMARY (fixed in ac4dfb5 + this audit):

1. Group repeat=1 with repeat_forever=false
   dashboard.py _run_group() while-loop exited after iteration 0 when repeat was 1.
   Location: dashboard.py:2498  `while ... (forever or iteration < repeat)`

2. sequence_playlist_mode=ordered picks ONE file per iteration
   sequence_playlist.py resolve_steps() pick_rotating_filename() at line 303-304.
   With repeat=1 only the first playlist slot ran.

3. Identity reset ran after EVERY iteration (before cycle fix)
   dashboard.py _run_one_phone called full_identity_reset unconditionally after each
   run. Fixed at dashboard.py:2477-2486 with is_playlist_cycle_end() gate.

SECONDARY (fixed in this audit — identity tail on every file):

4. _enforce_ip_id_tail() appended rotate_identity/wait/full_reset to EVERY ordered/random
   batch, and JSON sequence files already embed that tail.
   sequence_playlist.py:303-304 (old) caused identity rotation after each file even when
   dashboard deferred cycle-end reset.
   Fix: strip per-file identity tail in ordered/random; enforce tail once for series only;
   dashboard full_identity_reset at cycle end.

EARLY EXIT LOCATIONS (historical — no longer active after fixes):
  - dashboard.py:2498 — loop exit when repeat exhausted (mitigated by _effective_group_repeat)
  - dashboard.py:2477 — identity every iteration (mitigated by is_playlist_cycle_end)
  - sequence_playlist.py ordered path — one file per iteration BY DESIGN (mitigated by repeat bump)

================================================================================
PHASE 2: REPEAT / CYCLE BEHAVIOR
================================================================================

Config fields (groups[].repeat, groups[].repeat_forever):
  - repeat: int >= 1, default 1
  - repeat_forever: bool, default false

After playlist completes once (ordered, N files, repeat bumped to N):
  - Group logs "Done ✓" and stops (unless repeat_forever=true)
  - Tor processes STAY RUNNING (no stop_all mid-farm)
  - full_identity_reset runs once at last iteration (is_playlist_cycle_end)

Secondary playlist (sequence_playlist_secondary):
  - ordered/random: one pick from A AND one from B per iteration (concatenated steps)
  - series: all A files then all B files in one iteration
  - cycle length = max(len(A), len(B)) or len(A)+len(B) if shuffle=combined

repeat_forever=true:
  - Loop never exits on repeat count; identity resets each full playlist cycle

================================================================================
RECOMMENDED groups_config.json SETTINGS
================================================================================

For run ALL playlist files, repeat forever, Tor always on during farm:

  {
    "name": "Group 1",
    "repeat": 1,
    "repeat_forever": true,
    "stagger_secs": 30,
    "phones": {
      "<adb_serial>": {
        "sequence_playlist": ["900x1600/no-ad/file1.json", "..."],
        "sequence_playlist_secondary": [],
        "sequence_playlist_mode": "series",
        "sequence_playlist_shuffle": "none",
        "steps": []
      }
    }
  }

Mode guide:
  - series + repeat_forever: BEST for continuous filming (all files every cycle)
  - ordered + repeat_forever: one file per iteration, cycles forever through list
  - ordered + repeat=1: runs each file once then stops (repeat auto-bumped to N)

Tor: start farm via wizard Launch; do NOT click Turn off Tor between cycles.
Identity: automatic at end of each full playlist cycle (dashboard full_identity_reset).
